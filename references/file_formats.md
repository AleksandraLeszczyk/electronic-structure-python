# File Formats in Computational Quantum Chemistry

A reference guide to common file formats encountered in quantum chemistry and related computational fields.

---

## XYZ

**Extension:** `.xyz`

The XYZ format is one of the simplest and most widely supported molecular geometry formats. It stores Cartesian coordinates of atoms in Ångströms.

**Structure:**
```
<number of atoms>
<comment line>
<element>  <x>  <y>  <z>
...
```

Multiple sequential geometries (e.g., from a geometry optimization or MD trajectory) can be concatenated in a single file, with each frame starting with its own atom count line. Used by virtually every quantum chemistry and molecular visualization program (ORCA, GAMESS, Avogadro, VMD, ASE, etc.).

---

## Molden

**Extension:** `.molden`

A format developed for the Molden visualization program. It stores molecular geometry, basis set information, molecular orbital (MO) coefficients, and MO energies/occupations. Optionally includes vibrational frequencies and normal modes.

**Key sections:**
- `[Atoms]` — nuclear coordinates
- `[GTO]` — Gaussian-type orbital basis set definition
- `[MO]` — orbital energies, occupations, symmetry labels, and expansion coefficients
- `[FREQ]` / `[FR-COORD]` / `[FR-NORM-COORD]` — vibrational data

Widely produced by ORCA, Gaussian, Molpro, Turbomole, and PSI4. Used for visualizing electron densities, MOs, and natural bond orbitals (NBOs) in tools such as Molden, Multiwfn, and Avogadro.

---

## Cube

**Extension:** `.cube`

Originally from Gaussian, the Cube format stores volumetric scalar field data on a regular 3D grid. The grid values are typically electron density, electrostatic potential (ESP), or molecular orbital amplitudes.

**Structure:**
```
<comment line 1>
<comment line 2>
<natoms>  <origin x>  <origin y>  <origin z>
<nx>  <x-step vector>
<ny>  <y-step vector>
<nz>  <z-step vector>
<atom Z>  <charge>  <x>  <y>  <z>  (repeated natoms times)
<grid values row by row>
```

Coordinates and grid spacings are in Bohr. Supported by nearly all visualization software (VMD, VESTA, Avogadro, Chimera) and analysis tools (Multiwfn, critic2). Generated by Gaussian, ORCA, CP2K, Quantum ESPRESSO, and many others.

## FCIDUMP

**Extension:** `.fcidump` or `FCIDUMP` (no extension)

A plain-text format that stores the one- and two-electron integrals needed to define a second-quantized electronic Hamiltonian in a given orbital basis. It is the standard input format for Full Configuration Interaction (FCI) and other post-Hartree–Fock active-space methods.

**Structure:**
```
 &FCI NORB=<n>, NELEC=<N>, MS2=<2S>, ...
 /
 <value>  <i>  <j>  <k>  <l>
 ...
```

- Lines with four non-zero indices: two-electron integrals `(ij|kl)`
- Lines with two non-zero indices: one-electron integrals `h_ij`
- Line with all-zero indices: nuclear repulsion energy

Used as input for DMRG codes (Block, CheMPS2), selected CI codes (DICE, SHCI), and quantum computing frameworks (OpenFermion, PySCF, Qiskit Nature).

## Gaussian Formatted Checkpoint (fchk)

**Extension:** `.fchk` or `.fch`

A human-readable text file produced by Gaussian that contains a comprehensive snapshot of a calculation: geometry, basis set, MO coefficients, density matrices, forces, Hessian, population analysis, and more. It is the formatted (ASCII) counterpart to Gaussian's binary `.chk` checkpoint file.

**Structure:** keyword–value pairs with a type and length specifier:
```
Total Energy                               R                 -7.61882416932E+01
Number of atoms                            I                 3
Current cartesian coordinates              R   N=           9
  <values...>
```

Serves as a portable interchange format for post-processing: natural bond orbital (NBO) analysis, topology analysis (AIMAll, Multiwfn), visualization (GaussView, Avogadro), and population/charge analysis. Also readable by ORCA and other codes via format converters.

## PDB (Protein Data Bank)

**Extension:** `.pdb`

The legacy coordinate format of the RCSB Protein Data Bank. It encodes atomic positions, element types, residue names, chain identifiers, occupancy, and temperature factors (B-factors) in fixed-width columnar records.

**Key record types:**
- `ATOM` / `HETATM` — atomic coordinates and metadata
- `CONECT` — explicit bond connectivity
- `HEADER`, `REMARK` — metadata and notes
- `CRYST1` — unit cell parameters (for crystal structures)

While PDB has largely been superseded by mmCIF/PDBx for large structures, it remains the standard input format for molecular dynamics (AMBER, GROMACS, NAMD, OpenMM), docking (AutoDock, Vina), and QM/MM setups. Coordinate precision is limited to three decimal places in Ångströms.

## POSCAR / CONTCAR

**Extension:** none (files named `POSCAR`, `CONTCAR`, `POSCAR_*`)

The primary structure input format for VASP (Vienna Ab initio Simulation Package). It defines a periodic unit cell and the fractional or Cartesian coordinates of all atoms within it.

**Structure:**
```
<comment / system name>
<universal scaling factor>
<lattice vector a1>
<lattice vector a2>
<lattice vector a3>
<element symbols>
<atom counts per element>
Selective dynamics  (optional)
Direct / Cartesian
<coordinates>
```

`POSCAR` is the initial structure; `CONTCAR` is written by VASP at the end of a run and contains the final relaxed geometry (same format). Widely supported by ASE, pymatgen, Phonopy, VESTA, and other periodic-DFT toolchains. Closely related formats include `POSCAR`-style files used by Phonopy, ABINIT, and FHI-aims converters.

## Summary Table

| Format       | Primary Content                          | Typical Use Case                              |
|--------------|------------------------------------------|-----------------------------------------------|
| XYZ          | Atomic coordinates                       | Input/output geometry, trajectories           |
| Molden       | Geometry, basis, MOs, frequencies        | Orbital and vibration visualization           |
| Cube         | Volumetric scalar fields on 3D grid      | Density, ESP, MO isosurface plots             |
| FCIDUMP      | One- and two-electron integrals          | FCI, DMRG, selected CI, quantum computing     |
| Gaussian fchk| Full calculation checkpoint (ASCII)      | Post-processing, population analysis, NBO     |
| PDB          | Atomic coords, residue/chain metadata    | Biomolecular MD, QM/MM, docking               |
| POSCAR       | Periodic cell + atomic coordinates       | Periodic DFT (VASP), solid-state calculations |
